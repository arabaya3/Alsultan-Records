## Roles

`app_role` enum: `owner`, `admin`, `staff`, `customer`.
- Stored in `profiles.role`; mirrored into JWT via a custom access token hook (`auth.custom_access_token_hook`) as claim `app_role`, plus `aal` from Supabase.
- Helper SQL functions (security definer, stable, `search_path=''`): `app.current_role()`, `app.is_staff()` (owner|admin|staff), `app.is_admin()` (owner|admin), `app.is_owner()`, `app.customer_id()` (customer row linked to auth.uid()), `app.require_mfa()` (staff roles must have aal2 when `app_settings.require_staff_mfa` = true), `app.is_active()` (profile not disabled).
- Users can NEVER update `profiles.role`, `profiles.disabled`, or `customers.user_id` — column privileges revoked + trigger guard.
- Initial owner: RPC `bootstrap_initial_owner(p_token text)` succeeds only if no owner exists AND token matches the hash stored in `private.bootstrap` (set by operator via SQL). One-shot.

Permission matrix (summary; full in security-model.md):

| Area | owner | admin | staff | customer |
|---|---|---|---|---|
| Public content edit/publish | ✔ | ✔ | — | — |
| Customers, bookings, events | ✔ | ✔ | read assigned events | own only |
| Media upload | ✔ | ✔ | assigned events | — |
| Quotes/contracts | ✔ | ✔ | — | own: read, accept/approve |
| Payments/refunds/expenses, financial reports | ✔ | read | — | own payments read |
| Staff, equipment | ✔ | ✔ | read own assignments | — |
| Users/roles, settings, backups | ✔ | — | — | — |

## Schema contract (schema `public` unless noted; all ids `uuid default gen_random_uuid()`, `created_at/updated_at timestamptz`)

Money: `bigint` minor units (agorot/cents) + `currency char(3)` default `'ILS'`. Totals are computed by triggers/RPC, never trusted from the client.

Content & settings
- `business_settings` (single row, public read): name, tagline, phone, whatsapp, email, address, instagram, facebook, hero_media_id, canonical_base_url.
- `app_settings` (single row, owner only): require_staff_mfa, turnstile_enabled, booking_rules jsonb.
- `services`: slug unique, title, summary, body, cover_media_id, sort_order, is_published.
- `service_categories` (wedding, engagement, graduation, festival, commercial, dj, livestream, production).

People
- `profiles`: id = auth.users.id, full_name, phone, role app_role default 'customer', disabled bool, mfa_required bool.
- `customers`: user_id (nullable, unique, → profiles), full_name, phone, email, city, notes (staff-only via view), created_by.
- `staff_members`: profile_id nullable, full_name, specialty, phone, active.

Booking & events
- `booking_requests`: tracking_code unique (public, random 10 chars), customer_id nullable, contact fields, event_type, event_date, city, venue, guests, services text[], message, status `booking_status` (`new → contacted → quoted → confirmed → cancelled | declined`), idempotency_key unique, source ip hash. Transitions enforced by trigger + `booking_stage_history`.
- `events`: customer_id not null, booking_request_id, title, event_type, event_date, venue, city, status `event_status` (`planned, shooting, editing, delivered, archived`), public_slug unique nullable, publication_consent `consent_status` (`none, requested, granted, revoked`), consent_at, consent_by, is_published, featured, featured_order, seo_title, seo_description, highlight, coverage_notes, production_note, equipment_note.
- Public project = event where is_published AND publication_consent='granted' (check constraint + trigger; revoking consent unpublishes).

Media
- `media_assets`: event_id nullable, owner customer via event, bucket (`public-media` | `private-media`), path unique, kind (`image`,`video`,`document`), mime, bytes, width, height, duration_s, variants jsonb ({thumb, display} paths), visibility (`private`,`public`), sort_order, upload_status (`pending, ready, failed`), uploaded_by. Public visibility allowed only when the event is publishable.
- `deliverables`: event_id, kind (`gallery`,`video`,`album`,`files`), title, status (`in_progress, review, revision_requested, approved, delivered`), due_at.
- `deliverable_revisions`: deliverable_id, revision_no (unique per deliverable), media_asset_id, notes, created_by. Video comments bind to a revision.
- `video_comments`: revision_id, author profile, timecode_ms int ≥0, body, resolved bool.
- `album_selections`: event_id, customer_id, status (`draft, submitted, locked`), unique(event_id) for the draft; `album_selection_items`: selection_id, media_asset_id (must belong to same event — validated in trigger), note, unique(selection_id, media_asset_id). RPC `submit_album_selection(event_id)` writes immutable `album_selection_snapshots` (jsonb of ids + notes, count, submitted_at).

Commercial
- `quotes`: quote_no unique, customer_id, event_id, status (`draft, sent, accepted, rejected, expired`), currency, subtotal, discount, total (computed), valid_until; `quote_items`: description, qty numeric, unit_price bigint, line_total computed.
- `contracts`: quote_id, customer_id, event_id, status (`draft, sent, approved, void`), current_version_id; `contract_versions`: contract_id, version_no, body, total, deposit_required, content_hash (sha256), immutable after insert. RPC `customer_approve_contract(version_id, content_hash)` approves only the exact version.
- `payments`: customer_id, event_id, contract_id, kind (`payment`,`refund`), amount bigint >0, method, received_at, reference, idempotency_key unique, recorded_by. `expenses`: event_id nullable, category, amount, spent_at, recorded_by.
- View/RPC `event_financials(event_id)` and `admin_financial_summary(from,to)` (owner/admin) compute contracted, paid, refunded, balance.

Operations
- `event_staff_assignments` (event_id, staff_id, role_label; unique pair; conflict rule: same staff on two events on the same date → rejected unless `override_reason`).
- `equipment` (name, serial, status `available, assigned, maintenance, retired`), `equipment_assignments` (equipment_id, event_id, out_at, returned_at; exclusion: no overlapping open assignments), `equipment_maintenance`.
- `support_requests` (tracking_code, customer_id nullable, subject, status `open, pending, resolved, closed`), `support_messages`.
- `reviews` (customer_id, event_id, rating 1–5, body, status `pending, approved, rejected`, moderated_by). Public sees approved only.
- `notifications` (recipient profile, kind, payload, read_at).
- `audit_events` (actor, action, entity_type, entity_id, before jsonb, after jsonb, at) — insert ONLY by triggers/security-definer functions; no direct insert grant.
- `backup_runs` (kind, status `running, completed, partial, failed`, table_counts jsonb, object_counts jsonb, errors jsonb, location, started_at, finished_at).

Storage buckets: `public-media` (public read, write admin only), `private-media` (no public access; read via short-lived signed URLs minted server-side after ownership check; path convention `events/{event_id}/{asset_id}/{variant}.{ext}`).

## Public form endpoints (Edge Functions, Deno)
`submit-booking`, `track-booking`, `submit-support`, `track-support`: verify Turnstile server-side when `TURNSTILE_SECRET` set, rate limit by ip-hash in `private.rate_limits`, Zod-equivalent validation, idempotency key. Next.js server actions may call these or call the equivalent SECURITY DEFINER RPCs; choose one path per form (decided: **Next server action → RPC `public_submit_booking` with Turnstile verified in the server action**; Edge Functions kept only if a non-Next client needs them).
