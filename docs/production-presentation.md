# تحسين العرض ضمن تصميم الإنتاج (fix/production-presentation)

- **الأساس:** `c015839`، وهو آخر `master` متحقق منه.
  - **ليس commit إنتاج مؤكدًا.** حاولت القراءة فقط عبر الوسائل الرسمية:
    - GitHub API: لا deployments ولا commit statuses ولا environments لهذا المستودع.
    - Vercel: الربط يحتاج إعادة تفويض.
  - CSP الموقع الحالي خالٍ من إضافات الاستوديو، لكن هذا وحده لا يثبت تطابق النسخة.
- **النطاق:** عرض فقط. لا migration، ولا تغيير بيانات أو أسعار أو اشتراكات، ولا ريلز أو فيسبوك. ترتيب الألبومات والتواريخ والهيرو والريلز في فرع منفصل: `feature/album-publishing-reels`.

## ما تغيّر

| الجزء | التغيير |
|---|---|
| صفحة العرض | الوصف يُعرض أقسامًا. كل خدمة مرقّمة بطاقة فيها بنودها، وكل سطر قصير يسبق قائمة يصبح عنوانًا لها. |
| «التسليمات والهدايا» | قسم مميّز، فقط حين يكتبه المالك بنفسه. |
| توزيع الصفحة | عمودان على الكمبيوتر، وعمود واحد على الهاتف. بلا عمود فارغ حين لا توجد صورة. |
| رأس الصفحة | السعر والفترة ومدة العرض بعناوين واضحة، مع زر واتساب. |
| الوصف الحر | يبقى نصًا منظّمًا بطول سطر مقروء. |
| أغلفة الألبومات | `srcset`/`sizes` بالعرض الحقيقي للعمود: نسخة 480px أو 1600px. الأغلفة كاملة (contain) كما كانت. |
| الرئيسية | الألبومات بعمودين على الهاتف. روابط «كل الألبومات» و«كل الأعمال» بنص ظاهر. |
| صفحة الألبوم | الصور أقرب للعنوان والأزرار. |

ما لم يتغير:
- النصوص والأسعار وحالة إظهار السعر وتواريخ العروض.
- الإيموجي المخزّن.
- المحلّل الأصلي `parseTextBlocks`. التجميع طبقة عرض فوقه.
- العارض: كان يتلاشى عند الفتح ويحترم تقليل الحركة، فلم يُعدّل.

## الفحوص — نتيجة نهائية موحدة

**البيئة:** worktree مستقل `alsultan-a` وقاعدة محلية مستقلة، مع كل ملفات الاختبار المحلية: fb-import وupload-fixtures وraw-samples.

**التشغيل الكامل** على `d75786e`، وهو آخر كود التطبيق. بعده تغيّر ملف اختبار واحد فقط (OD5 في `28a8cef`)، وشُغّل منفصلًا.

| الفحص | النتيجة |
|---|---|
| TypeScript | نجح |
| ESLint | نجح |
| build | نجح |
| بقايا الاستوديو في `.next/static` و`public` | لا شيء |
| Vitest | 174/174، بلا تخطٍّ |
| Playwright chromium + mobile، الحزمة كاملة | 232 نجح، 1 فشل، 17 تخطٍّ (+4 اختبارات لاحقة في نفس الملف لم تعمل) |
| `offer-details` على `28a8cef` | 5/5 (OD1–OD5) |

**تخطّيات Vitest:** كانت 6 في تشغيل سابق (`raw.test.ts` `decodeRaw`، و`rules.test.ts` «recognises the real CC0 RAW samples»). شرطها وجود `.cache/raw-samples`، وبعد توفيره صارت 0.

**إخفاق Playwright (`consent-revocation` «same URL is 404 immediately»):** إخفاق متقطع موجود قبل هذا الفرع.
- **العَرَض:** رسالة الحالة تبقى «سُجّلت موافقتك» بعد ضغط السحب.
- **الدليل:** نفس الاختبار مكررًا 5 مرات على `c015839` نفسه فشل مرتين في دفعة ونجح 30/30 في أخرى.
- الفرع لا يلمس كود البوابة (portal) إطلاقًا.
- النتيجة: الاختبارات الأربعة اللاحقة في نفس الملف (serial) لم تعمل في ذلك التشغيل، ونجحت في تشغيلات منفصلة.

**تخطّيات المتصفح (17 في chromium):**

| العدد | الاختبار | السبب | هل شُغّل منفصلًا؟ |
|---|---|---|---|
| 1 | `album-upload-stress` S1 | اختياري، `STRESS=1` | لا |
| 1 | `album-upload-v2` V8 | يحتاج `ALBUM_RAW_DECODE_TIMEOUT_MS=300` | لا |
| 2 | `auth-links` | شرط `site_url` في config | لا |
| 3 | `empty-states` | يحتاج `EMPTY_STATE=1` وتطبيقًا على قاعدة فارغة | لا |
| 1 | `measure-upload` | اختياري، `MEASURE=1` | لا |
| 1 | `photos` «empty state» | لا ينطبق: توجد ألبومات منشورة | لا |
| 4 | `qa-journeys` و`qa-responsive` | `test.skip` في الكود، سابقة | لا |
| 3 | `ui-audit-visual` | اختياري، `VISUAL=1` | لا |
| 1 | OD5 | استعلام الصورة كان خاطئًا | **أُصلح وشُغّل: نجح** |

**WebKit** (`PW_WEBKIT=1`، عبر بوابة محلية على 127.0.0.1 تزيل `upgrade-insecure-requests` فقط): العروض، وقائمة الألبومات، وصفحة الألبوم والعارض.
- **الإخفاقات الثلاثة** (OD4 وK1 وUA5) كلها تسجّل الدخول للإدارة. WebKit يرفض كوكيز Secure على http، وهذا قيد بيئي معروف، ولم تُشغّل على https محليًا.
- **اكتُشف وأُصلح** (`d75786e`): عودة التركيز إلى الصورة بعد إغلاق العارض، وبقاء Tab داخل العارض.
  - كان الاثنان يفشلان على WebKit في `c015839` أيضًا.
  - السبب: Safari لا يركّز الزر عند النقر، وTab الافتراضي فيه يتخطى الروابط.
  - بعد الإصلاح نجحا على WebKit.

## اختبارات جديدة
| الاختبار | ما يتحقق منه |
|---|---|
| OD1 | كل سطر من الوصف يظهر مرة واحدة وبترتيبه |
| OD2 | قسم التسليمات والهدايا مميّز، وعمودان على الكمبيوتر، وبلا عمود فارغ |
| OD3 | النص الحر عند 320px |
| OD4 | نشر عرض من مسار الإدارة الفعلي يُظهره للعامة فورًا (انظر أدناه) |
| OD5 | الحالات الأربع (سعر/صورة) على 390 و1440: لا عمود فارغ، والصورة كاملة داخل الصفحة، وأزرار ≥44px، ولا تمرير أفقي |
| AC1 | النسخة المختارة كافية الدقة: thumb على 1×، وdisplay على 2× و3× |
| AC2 | فشل تحميل الغلاف يُبقي الإطار 2:3 والعنوان والرابط |
| AC3 | سحب نشر الصورة يجعل thumb وdisplay معًا 404 فورًا |

- **OD4:** يدفّئ كاش العروض أولًا، ثم يطلب الصفحة مرة واحدة بلا انتظار، فيثبت أن `updateTag` عند الحفظ يُبطل الكاش. انتظار OD1–OD3 بقي فقط لأنها تُدخل البيانات مباشرة في القاعدة. لا endpoint خاص بالاختبارات.
- **AC3:** الرأسان `CDN-Cache-Control: no-store` و`Cache-Control: private` يمنعان أي كاش مشترك. ما خزّنه متصفح زائر من قبل يبقى حتى 5 دقائق (`private, max-age=300`)، وهي سياسة قائمة قبل هذا الفرع وتنطبق على النسختين.
- **لقطات الحالات الأربع:** `docs/screenshots/production-presentation/cases/`.

**لم يُختبر:** هاتف حقيقي، وقارئ شاشة، وWebKit لمسارات الإدارة (تحتاج https).
