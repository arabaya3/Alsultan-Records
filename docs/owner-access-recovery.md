# استعادة وصول المالك + حدود النسخة الاحتياطية

الموقع ما فيه صفحة تسجيل، ولا يوجد «باب خلفي» داخل الموقع نفسه. أي استعادة تمرّ عبر **حساب Supabase** (لوحة التحكم بالمشروع `dyuixzxmmeiypvawzmty`) أو حساب **Vercel**. لذلك:

> **أهم شي:** حساب Supabase وحساب Vercel هم «المفتاح الرئيسي». فعّل عليهم التحقق الثنائي، واحفظ رموز الاسترداد (recovery codes) تبعهم على ورق في مكان آمن. إذا ضاعوا هم كمان، الاستعادة تصير عبر دعم Supabase/Vercel وإثبات الملكية.

## 1) نسيت كلمة المرور (والجوال اللي عليه تطبيق المصادقة معك)
1. `/login` ← «نسيت كلمة المرور» ← أدخل بريدك.
2. افتح الرابط **من نفس المتصفح** اللي طلبته منه (القوالب الافتراضية للإيميل ما بتشتغل من جهاز ثاني — راجع `docs/auth-links.md`). الحد: طلب واحد كل 60 ثانية، وعدد محدود بالساعة بدون SMTP خاص.
3. اختر كلمة جديدة ← ادخل ← رمز تطبيق المصادقة كالعادة.

إذا الإيميل ما وصل: من لوحة Supabase ← Authentication ← Users ← المالك ← **Send password recovery**، أو يضبط المسؤول التقني كلمة مؤقتة من نفس الشاشة، وأنت بتغيّرها أول دخول.

## 2) ضاع/تغيّر جهاز MFA (تطبيق المصادقة)
رموز الاسترداد غير موجودة في الموقع، فالحل يمرّ عبر Supabase (يعمله صاحب حساب Supabase فقط):
1. لوحة Supabase ← Authentication ← Users ← حساب المالك ← قسم **MFA factors** ← احذف العامل القديم (Unenroll).
   بديل SQL (SQL Editor): `delete from auth.mfa_factors where user_id = '<owner user id>';`
2. سجّل دخول عادي بالموقع. لأن `mfa_required` مفعّل على حساب المالك، الموقع **يجبرك** تسجّل تطبيق مصادقة جديد قبل ما تدخل `/admin`.
3. تأكد: `/admin` يفتح بعد الرمز الجديد، وصفحة المستخدمين بـ Supabase تعرض عاملًا واحدًا فقط.

لا تعطّل `mfa_required` ولا المفتاح العام `require_staff_mfa` كحل مؤقت.

## 3) ضاع البريد نفسه أو الحساب مقفول
- من Supabase ← Users: يمكن تعديل بريد المستخدم لبريد جديد يملكه المالك (يعمله صاحب حساب Supabase)، ثم الخطوة 1.
- الصلاحية محفوظة في `profiles.role = 'owner'` مرتبطة بنفس `id`، فما في داعي لإنشاء حساب جديد. **لا تنشئ مالكًا ثانيًا بالـ SQL** بدون قرار واعٍ: سكربت `staging-bootstrap-owner.mjs` مصمم لأول مالك فقط.
- اقتراح (غير مفعّل): حساب «طوارئ» ثاني بدور admin وجهاز MFA مختلف، محفوظ عند شخص موثوق. هذا قرار للمالك.

## 4) ما الذي لا تغطيه النسخة الاحتياطية الحالية (`npm run backup`)
النسخة تحتوي: 49 جدولًا (المحتوى، الحجوزات، العقود، المدفوعات، الـ audit…)، قائمة المستخدمين (ids، بريد، بيانات وصفية)، وكل ملفات التخزين **بما فيها الأصول الخاصة**، مع manifest وsha256 لكل ملف.

**لا** تحتوي:
| الشيء | ليش / وين موجود |
|---|---|
| كلمات المرور (hashes) وأسرار TOTP | الـ Admin API ما بيصدّرهم. بعد الاسترجاع كل مستخدم يعمل «نسيت كلمة المرور» ويسجّل MFA من جديد. نسخة كاملة للحسابات تحتاج `pg_dump` (Procedure A/B في `docs/backup-restore.md`). |
| أسرار الخادم (`.env*`، مفاتيح Supabase، `JOBS_SECRET`، أسرار Vault) | متعمّد — ما بتنحفظ بالنسخة ولا بـ Git. بعد أي استرجاع لمشروع جديد تنولّد مفاتيح جديدة. |
| إعدادات Supabase وVercel (المشروع، الدومين، متغيرات Vercel، إعدادات Auth، قوالب الإيميل) | تُعاد يدويًا حسب `docs/staging.md` و`docs/handoff.md`. |
| بنية قاعدة البيانات والصلاحيات وcron | ليست بالنسخة، لكنها في Git (`web/supabase/migrations`). |
| ملفات الفيديو الأصلية للأعراس | غير مرفوعة على الموقع؛ الفيديوهات تُعرض من YouTube، **ويوتيوب ليس نسخة احتياطية**. احتفظ بالأصول عندك. |
| فيديو البرومو والصوت | موجودين في Git (`web/public/promo`)، والنسخة تسجّل sha256 فقط. |
| الكود | في Git (الفرع `rebuild/nextjs`). |

وأيضًا: النسخة **محلية على هذا الجهاز** (`web/backups-local/`). ليست نسخًا دوريًا خارجيًا حتى نحدد وجهة (قرص خارجي/Drive/R2) ونفعّل جدولة ونجرّبها.
